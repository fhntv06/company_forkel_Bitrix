## Цель
Страницы каталога, коллекции, товара и «Новинки» работают на реальных инфоблоках `catalog`, `collections`, `catalog_offers` и выглядят как V4.

## Область изменений
Разрешено: `backend/www/local/**`, `backend/www/catalog/**`, `backend/www/collections/**`, `docs/**`. Запрещено: ядро, `prototype/`.

## Шаги (после каждого — проверка владельцем на рендере)
- **2.1 (владелец, админка):** торговый каталог с ТП, значения `COLOR`, свойства товара (`COLLECTION`, `MATERIAL`, `NEW`, `MORE_PHOTO`), разделы, ЧПУ, 5–10 тестовых товаров с ТП, ценами и остатками. Список — `bitrix-implementation-plan.md`, «Ещё не создано».
- **2.2 (код):** страница каталога `/catalog/`: ссылки на категории, поиск, сортировка, сетка карточек, умный фильтр (коллекция, цвет, материал, наличие, цена), пустое состояние.
- **2.3 (код):** страница товара: галерея, выбор цвета (ТП), цена, «В корзину», характеристики, кнопки файлов.
- **2.4 (код):** страница коллекции `/collections/<код>/`.
- **2.5 (код):** «Новинки» `/catalog/new/` по флагу `NEW`.

## Критерии приёмки
- [ ] `php -l` без ошибок для всех PHP-файлов.
- [ ] Страницы открываются на тестовых данных, ссылки и адреса (ЧПУ) совпадают с настройками инфоблоков.
- [ ] Разметка карточек, фильтра и страницы товара сохраняет классы V4.
- [ ] Данные берутся из инфоблоков и модулей `catalog`/`sale`, без хардкода товаров.
- [ ] Прототип V4 не изменён.
- [ ] Независимый QA (статический) и проверка владельцем на рендере.

## Отчёт
- **Сделано (шаги 2.2–2.5 и блоки товара):**
  - `/catalog/` и разделы: категории, поиск (название, артикул `ARTICLE`), сортировка, умный фильтр (коллекция, цвет, материал, цена; GET-параметры), карточки V4 с фото, артикулом, цветом, коллекцией и материалом, цветными точками из торговых предложений, ценой «от» и наличием. Общий код списка — `partials/catalog_list.php`, `fk_catalog_list()`.
  - Страница товара: фото и «Скачать фото», код (`PRODUCT_CODE`), артикул, цена, наличие (с остатком при количественном учёте), выбор цвета по торговым предложениям, количество, «В корзину» (`/local/ajax/add2basket.php`, штатный `Basket::addProduct`), «Купить в 1 клик» и «Задать вопрос» (окно `feedback`, режим `oneclick`, контекст товара), кнопки «3D-модель», «Видео» (окно), «Инструкция», характеристики с копированием, описание под характеристиками, «Сопутствующие» (`ACCESSORIES`) и «Похожие» товары.
  - Коллекции: `/collections/<код>/` — hero и список с фильтром по `COLLECTION`; `/collections/` ведёт на `/catalog/`. Правило в `urlrewrite.php` (ключ 8).
  - «Новинки»: `/catalog/new/` по флагу `NEW`.
  - nginx: 301 на адрес со слэшем для `/catalog/` и `/collections/`.
- **Решения и допущения:** «Избранное» и «В корзину» в карточке списка не выводятся (корзина — на странице товара, избранное — В-5); «Новинки» — физическая папка, раздел каталога с кодом `new` создавать нельзя; параметры списка коллекций дублируют `catalog/index.php` (`fk_catalog_params()`); наличие и цена-сортировка зависят от настроек магазина.
- **Проверки:** `php -l` всех PHP и `node --check` JS шаблона — выполнены. Независимый QA (статический), 2 раунда, `docs/qa/TASK-005-qa.md`: раунд 1 FAIL (P1: `sessid` в кеше страницы товара) → исправлено (`/local/ajax/sessid.php`) → раунд 2 PARTIAL, открытых P0–P2 нет. Рендер в Битриксе 26.150.0 владелец проверял по шагам: каталог, карточки, страница товара, поля, кнопки; страницы коллекции и «Новинки», а также блоки «Сопутствующие/Похожие» на момент отчёта владельцем на рендере не подтверждены.
- **Открытые P3:** QA-003 (`feedback.php`: GET `?success` без проверки хэша, нет предела длины и частоты), QA-004 (формат телефона на сервере), QA-006 (nginx: код элемента с точкой).
- **Не сделано:** кнопка «В корзину» и «Избранное» в карточке списка; палитра и материалы коллекции на странице коллекции; фильтр «Наличие».
- **Следующий шаг:** Этап 3 (главная) — нужны инфоблоки `features`, `projects`, `solutions`, `interiors`, `pro` и области главной.
