# Онлайн-оплата: интернет-эквайринг Альфа-Банка (карты + СБП)

Статус: действует с 2026-11-27 (TASK-019, решение DEC-013). До получения доступов от банка сайт работает в песочнице.

## 1. Как устроено

| Что | Где |
|---|---|
| Платёжные системы «Онлайн-оплата банковской картой» (`forkel_alfabank_card`) и «Оплата через СБП» (`forkel_alfabank_sbp`) | БД, создаются/перенастраиваются миграцией `Version20261127110000` |
| Обработчик платёжной системы `forkelalfabank` | `backend/www/local/php_interface/include/sale_payment/forkelalfabank/` |
| Клиент API банка (register.do, getOrderStatusExtended.do, checksum) | `backend/www/local/php_interface/classes/AlfaBank.php` |
| Приём уведомлений банка (callback) | `/local/ajax/payment_webhook.php` |
| Страница оплаты и возврата из банка | `/personal/order/payment/` |
| Доступы и режим | переменные окружения `ALFABANK_*`, `SITE_URL`, `PAYMENT_SANDBOX` (см. `backend/.env.example`) |

Встроенный обработчик Битрикса «Альфа-Банк» (`alfabank`) не подходит: он работает с Альфа-Банком Беларуси (валюта BYN, ecom.alfabank.by). Поэтому сделан свой обработчик поверх REST API Альфа-Банка (Россия, платформа RBS). В админке у него настроек нет — всё берётся из окружения, ключи в БД и Git не хранятся.

**Путь покупателя.** Оформление заказа → кнопка «Оплатить» → сайт регистрирует заказ в банке (`register.do`) → платёжная страница Альфа-Банка (карта или СБП) → возврат на `/personal/order/payment/?result=success|fail&ORDER_ID=N`.

**Когда заказ становится оплаченным.** Только когда банк на запрос `getOrderStatusExtended.do` отвечает `orderStatus = 2` (деньги списаны) и сумма совпадает с оплатой в заказе. Проверка делается в двух местах (что сработает первым):
- callback банка на `/local/ajax/payment_webhook.php` (только для публичного HTTPS-адреса; сайт передаёт его банку в `dynamicCallbackUrl`);
- страница возврата покупателя (сама спрашивает статус у банка; параметру `result=success` в адресе не доверяет).

После оплаты заказ автоматически переходит в статус «Оплачен» (P) — опция `sale/status_on_paid`, задаётся миграцией.

## 2. Режимы

| Доступы `ALFABANK_*` | `PAYMENT_SANDBOX` | Что видит покупатель |
|---|---|---|
| не заданы | `1` (по умолчанию) | **Песочница сайта**: кнопка «Подтвердить тестовую оплату», банк не вызывается. Работает только для своего заказа и с действующей сессией. |
| не заданы | `0` | «Онлайн-оплата временно недоступна, менеджер свяжется». Заказ оформляется. |
| заданы, `ALFABANK_TEST_MODE=1` | любое | Тестовая платёжная страница банка (`alfa.rbsuat.com`), тестовые карты банка. |
| заданы, `ALFABANK_TEST_MODE=0` | любое | Боевая оплата (`payment.alfabank.ru`). |

## 3. Как включить (когда банк выдал доступы)

У банка нужно получить: логин и пароль API-пользователя магазина (обычно логин вида `xxx-api`) или токен; ключ для checksum callback-уведомлений (симметричный); подтверждение, что для магазина включён СБП; адреса API, если они отличаются от адресов по умолчанию.

1. Вписать в `backend/.env` (локально) или в переменные окружения сервера (боевой):
   ```env
   ALFABANK_USER=xxx-api
   ALFABANK_PASSWORD=...
   # или вместо логина/пароля: ALFABANK_TOKEN=...
   ALFABANK_CALLBACK_SECRET=...
   ALFABANK_TEST_MODE=1          # сначала тестовый контур
   SITE_URL=https://forkel.ru    # публичный адрес сайта
   PAYMENT_SANDBOX=0
   ```
2. Локально применить: `docker compose up -d php` (из `backend/`). Контейнер PHP получает эти переменные из `.env` через `docker-compose.yml`. На боевом — перезапустить PHP-FPM (или положить `.env` на уровень выше корня сайта: `\Forkel\Env` читает его, если переменной нет в окружении).
3. В личном кабинете мерчанта (или через поддержку банка) включить callback-уведомления с checksum на адрес `https://<домен>/local/ajax/payment_webhook.php`. Сайт передаёт этот адрес и в каждом заказе (`dynamicCallbackUrl`), но принимает ли его банк — зависит от настроек мерчанта.
4. Проверить на тестовом контуре (`ALFABANK_TEST_MODE=1`): заказ с оплатой картой → оплата тестовой картой банка → на странице возврата «Оплата прошла успешно», в админке заказ оплачен, статус «Оплачен». Затем отказ оплаты → «Оплата не прошла» и «Повторить оплату». Затем то же с СБП.
5. Для запуска: боевые доступы + `ALFABANK_TEST_MODE=0`, перезапуск PHP, одна настоящая оплата на маленькую сумму с последующим возвратом в кабинете банка.

Ничего в админке и коде менять не нужно.

## 4. Безопасность `payment_webhook.php`

| Запрос | Ответ |
|---|---|
| callback банка, доступы не заданы | 403 |
| callback банка, задан `ALFABANK_CALLBACK_SECRET`, checksum неверный или отсутствует | 403 |
| callback банка, заказ в банке не относится к этой оплате / сумма не совпадает | 400, оплата не ставится |
| песочница: без sessid, чужой заказ | 403 |
| любой запрос вне песочницы, не от банка | 403 |

Если `ALFABANK_CALLBACK_SECRET` не задан, подделать оплату всё равно нельзя: статус перепроверяется запросом к банку с доступами магазина. Но на боевом ключ всё равно задать. Журнал — `local/logs/payment_webhook.log` (без ключей; nginx его не отдаёт).

## 5. Что не сделано (нужны решения)

- **Чек 54-ФЗ.** Передача состава заказа банку для фискализации (`orderBundle`) не реализована, переменная `ALFABANK_FFD_ENABLED` зарезервирована. Нужно решение: фискализация через банк или своя онлайн-касса (кассы в Битриксе), система налогообложения, ставки НДС.
- **Возвраты** делаются в личном кабинете банка; из админки Битрикса возврат не отправляется.
- **СБП сразу QR-кодом на сайте** не сделан: оба способа оплаты ведут на платёжную страницу банка, где СБП доступен, если банк включил его для магазина.
- **Адреса API** взяты из публичной документации Альфа-Банка (`https://alfa.rbsuat.com/payment/rest/` — тест, `https://payment.alfabank.ru/payment/rest/` — боевой). При подключении сверить с банком; иначе задать `ALFABANK_API_URL` / `ALFABANK_TEST_API_URL`.
