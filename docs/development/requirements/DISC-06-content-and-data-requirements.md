# DISC-06 — Content and Data Requirements

## 1. Purpose

Документ определяет требования к содержимому сайта, структуре данных и источникам информации.

## 2. Content principles

Контент должен:
- Соответствовать утвержденному позиционированию Forkel.
- Использовать подтвержденные сведения.
- Иметь согласованную структуру.
- Быть пригодным для отображения на поддерживаемых устройствах.
- Не содержать фиктивных реквизитов, контактов или описаний проектов.

Отсутствующие сведения отмечаются как TBD до подтверждения.

## 3. Content inventory

Составить перечень контента для:
- Главной страницы.
- Контактов.
- Списка проектов.
- Детальных страниц проектов.
- Header и Footer.
- Поиска.
- Форм обратной связи.
- Системных сообщений.

Для каждой позиции указать владельца данных, источник, статус и необходимость согласования.

## 4. Project data model

Предварительная модель проекта:

| Field | Description | Status |
|---|---|---|
| id | Уникальный идентификатор | TBD |
| slug | URL-идентификатор | TBD |
| title | Название проекта | TBD |
| summary | Краткое описание | TBD |
| description | Полное описание | TBD |
| coverImage | Основное изображение | TBD |
| gallery | Дополнительные изображения | TBD |
| category | Категория проекта | TBD |
| order | Порядок отображения | TBD |

Дополнительные поля вводятся только при подтвержденной потребности.

Не все поля обязательно должны быть видимыми пользователю. Окончательная модель согласовывается с владельцем продукта и разработчиком.

## 5. Company information

Собрать и подтвердить:
- Официальное название компании.
- Фактический или юридический адрес в зависимости от требований.
- Телефон.
- Электронную почту.
- Иные утвержденные способы связи.
- Юридические реквизиты, если они должны публиковаться.

Каждое значение должно иметь проверяемый источник.

## 6. Contact form data

Определить:
- Поля формы.
- Обязательность полей.
- Ограничения длины и формата.
- Назначение каждого поля.
- Правила обработки персональных данных.
- Получателя и способ доставки сообщения.
- Сроки хранения данных, если применимо.

Не определять самостоятельно юридические основания обработки данных или тексты согласий.

## 7. Images and media

Для каждого изображения установить:
- Назначение.
- Источник.
- Связь с конкретной страницей или проектом.
- Требования к соотношению сторон.
- Альтернативный текст, когда необходим.
- Правила использования и права на публикацию.

Не использовать случайные изображения в качестве утвержденных материалов компании.

## 8. Content ownership

Для ключевых данных определить:
- Ответственного за предоставление.
- Источник истины.
- Статус подтверждения.
- Дату проверки, если данные могут изменяться.
- Условия обновления.

## 9. Content validation

Перед публикацией проверить:
- Корректность написания.
- Отсутствие фиктивных значений.
- Соответствие утвержденному позиционированию.
- Корректность ссылок.
- Соответствие изображений контенту.
- Наличие необходимых метаданных.
- Отсутствие внутренних заметок и служебных маркеров.

## 10. Open questions

- Кто предоставляет и утверждает тексты?
- Как формируется каталог проектов?
- Кто отвечает за обновление контактных данных?
- Требуется ли административная система управления контентом?
- Какие права на изображения и материалы подтверждены?
