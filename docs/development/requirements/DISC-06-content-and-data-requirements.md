# DISC-06 — Content and Data Requirements

- **Проект:** FORKEL — интернет-магазин электротехнической продукции
- **Платформа:** 1С-Битрикс: Управление сайтом
- **Статус:** Draft
- **Версия:** 0.2
- **Дата:** 2026-10-22

## 1. Назначение

Документ описывает контент и модели данных для интернет-магазина. Для сущностей сначала проверяется подходящая штатная модель Bitrix (инфоблоки, разделы, свойства, торговый каталог, торговые предложения, заказы и пользователи). Отдельные таблицы или хранилища не вводятся без технической причины.

## 2. Общие правила

- Использовать только подтверждённые данные компании и товарного каталога.
- Не придумывать цены, остатки, реквизиты, совместимость или описания проектов.
- Для каждого поля указывать источник истины, владельца и обязательность.
- Уточнить, какие данные ведутся в Bitrix вручную, а какие поступают из 1С.
- Если поле приходит из 1С, определить, может ли редактор менять его на сайте и что произойдёт при следующей синхронизации.
- Учитывать редакцию и версию Bitrix, установленные модули и формат обмена.

## 3. Контентные сущности

### 3.1. Товарный каталог

Предварительные поля товара:

| Поле | Назначение | Источник/статус |
|---|---|---|
| ID | Внутренний идентификатор Bitrix | Система |
| External ID | Идентификатор в источнике, если предусмотрен обмен | Уточнить по 1С |
| Название | Отображаемое имя | 1С или утверждённый источник |
| Артикул | Идентификатор товара для покупателя и поиска | 1С |
| Изображения | Основная и дополнительные фотографии | Источник/ответственный TBD |
| Краткое/полное описание | Информация о товаре | Уточнить источник |
| Категория/раздел | Место в каталоге | Согласовать с моделью 1С |
| Коллекция | Группировка коллекций | Уточнить, поле или отдельная сущность |
| Цена и валюта | Отображаемая цена | 1С/согласованный источник |
| Доступность/остаток | Состояние наличия | 1С/складская модель |
| Свойства | Механизм, цвет рамки, материал и другие подтверждённые характеристики | По фактическим данным |
| Активность | Публикация товара | Правило синхронизации TBD |

**Bitrix:** проверить инфоблок торгового каталога, типы товаров и поддержку SKU. Не создавать отдельные сущности вариантов, пока штатные торговые предложения покрывают модель.

### 3.2. Торговые предложения / варианты

Для товара с вариантами определить:
- Идентификатор предложения и связь с родительским товаром.
- Артикул, свойства варианта, цена и доступность.
- Правило выбора варианта на карточке товара.
- Источник и стабильность идентификаторов в 1С.
- Как обновляются свойства и остатки при обмене.

Совместимость вариантов должна основываться на реальных данных; не выводить её из визуального макета.

### 3.3. Корзина и заказ

Для корзины и заказа требуется определить:
- Состав заказа и связь позиции с товаром/предложением.
- Количество, цена на момент заказа и итоговая сумма.
- Контактные данные покупателя.
- Выбранные доставка и оплата.
- Статусы заказа и платежа.
- Идентификаторы и связь с 1С, если применимо.
- Правила обработки отмены, повторной отправки и ошибок.

**Bitrix:** использовать штатную модель корзины и заказа. Передача заказов в 1С относится к Этапу 2 по DEC-DEV-03; не считать её включённой только из-за наличия штатного модуля обмена.

### 3.4. Коллекции и категории

Определить связь коллекций с товарами и категориями. Выбрать модель после проверки выгрузки 1С: раздел каталога, свойство товара или отдельный инфоблок. Не смешивать разные подходы без бизнес-причины.

### 3.5. Проекты/портфолио

| Поле | Назначение | Статус |
|---|---|---|
| ID/slug | Идентификатор и URL | Согласовать |
| Название | Заголовок | Контент заказчика |
| Краткое/полное описание | Описание проекта | Контент заказчика |
| Обложка/галерея | Изображения | Контент заказчика |
| Категория/характеристики | Только если нужны для отображения | TBD |
| Порядок/дата | Сортировка или дата публикации | Согласовать |
| Активность | Публикация/снятие с публикации | Bitrix |

**Bitrix:** проверить инфоблок проектов и необходимые свойства. Публикация зависит от предоставления контента; поиск по проектам в MVP не входит.

### 3.6. Новинки и контентные страницы

Определить источник признака «Новинка»: свойство, дата публикации или управляемая подборка. Страницы «О компании», «Сотрудничество», контакты, главная и Footer должны редактироваться через предусмотренные средства Bitrix там, где требуется регулярное обновление.

## 4. Данные компании

Собрать и подтвердить:
- Официальное название.
- Адрес и режим работы, если публикуются.
- Телефоны и электронную почту.
- Юридические реквизиты.
- Социальные/мессенджер-ссылки.
- Географические координаты или адрес для карты.

Каждое значение должно иметь подтверждённый источник. Хранение в управляемой области Bitrix предпочтительно, если данные не поступают из иной утверждённой системы.

## 5. Формы и персональные данные

Для каждой формы определить поля, обязательность, ограничения, цель обработки, получателя, способ доставки, срок хранения и юридические тексты. Состав и основания обработки данных не выводятся из возможностей CMS и должны быть подтверждены ответственным лицом.

## 6. Изображения и медиа

Определить владельца файлов, допустимые форматы и размеры, правила alt-текстов, соотношения сторон, оптимизацию и порядок публикации. Не использовать изображения без подтверждённых прав. Для товарных изображений и проектов определить источник и правило замены/обновления.

## 7. Источники данных и синхронизация

| Область | Предполагаемый источник | Что нужно подтвердить |
|---|---|---|
| Товары, артикулы, цены, остатки | 1С — согласно DISC-01 | Конфигурация, формат, идентификаторы, расписание и правила конфликтов |
| Категории/коллекции | Выгрузка 1С или согласованная модель | Фактическая структура каталога |
| Проекты/страницы/контакты | Административная часть Bitrix | Ответственный и правила публикации |
| Заказы | Bitrix | Передача в 1С — Этап 2 |
| Платежи | Выбранный платёжный провайдер | Провайдер, callbacks/webhooks и статусы |
| Доставка | Bitrix и/или согласованный перевозчик | В MVP ручные/фиксированные правила; API — Этап 2 |

## 8. Администрирование и права

Определить роли сотрудников и доступ к редактированию товаров, контента и заказов. Использовать группы и права Bitrix, если они покрывают потребность. Отдельные роли и права проектировать только при подтверждённых бизнес-сценариях.

## 9. Проверки качества данных

- Обязательные поля заполнены.
- Идентификаторы не создают дубликаты при импорте.
- Цена и остаток имеют понятный источник.
- Свойства соответствуют фильтрам и характеристикам UI.
- Неактивные/удалённые товары обрабатываются согласованно.
- Товарные предложения связаны с родительским товаром.
- В шаблонах не отображаются пустые или фиктивные значения.

## 10. Открытые вопросы

- Получить тестовую выгрузку и описание конфигурации 1С.
- Утвердить структуру коллекций и свойства фильтрации по фактическим данным.
- Уточнить источник описаний и изображений товаров.
- Получить контент проектов и страниц.
- Утвердить поля форм и юридические тексты.
- Подтвердить редакцию/версию Bitrix и доступные модули.
