# DISC-10 — Analytics and Events

## 1. Purpose

Документ определяет требования к измерению пользовательских действий и оценке интернет-магазина FORKEL на 1С-Битрикс.

## 2. Status

Status: Proposed.

Необходимость аналитики, выбранная платформа и конкретные метрики требуют подтверждения владельцем продукта.

## 3. Measurement objectives

Если аналитика утверждена, определить измеримые цели, например:
- Просмотр основных разделов и карточек товаров.
- Поиск и использование фильтров каталога.
- Просмотр товара и добавление в корзину.
- Начало и успешное завершение оформления заказа, если аналитика ecommerce утверждена.
- Выбор доставки/оплаты, если событие можно безопасно и корректно измерить.
- Переходы к проектам и взаимодействие с контактной информацией.
- Открытие и успешная отправка формы обратной связи.

Цели должны соответствовать бизнес-задачам, утвержденным в DISC-01.

## 4. Proposed events

| Event ID | Event | Trigger |
|---|---|---|
| EVT-001 | page_view | Просмотр страницы |
| EVT-002 | product_open | Открытие детальной страницы товара |
| EVT-003 | search_submit | Отправка поискового запроса |
| EVT-004 | search_result_open | Открытие результата поиска |
| EVT-005 | feedback_open | Открытие формы обратной связи |
| EVT-006 | feedback_submit_success | Подтвержденная успешная отправка формы |
| EVT-007 | feedback_submit_error | Ошибка отправки формы |
| EVT-008 | contact_action | Использование контактной ссылки, если применимо |
| EVT-009 | add_to_cart | Добавление товара в корзину, если ecommerce-аналитика утверждена |
| EVT-010 | checkout_start | Начало оформления заказа, если ecommerce-аналитика утверждена |
| EVT-011 | order_success | Подтверждённое создание заказа; не считать событием простое нажатие кнопки |

Список предварительный и требует утверждения.

## 5. Event specification

Для каждого утвержденного события определить:
- Event name.
- Описание.
- Триггер.
- Обязательные параметры.
- Допустимые значения.
- Источник события.
- Условия отправки.
- Правила дедупликации.
- Ограничения приватности.

Не включать в аналитические события содержимое сообщений обратной связи, персональные данные или другие чувствительные сведения.

## 6. Conversion definition

Определить, какое действие считается целевым обращением.

Не приравнивать открытие формы к успешной отправке.

Событие успешной отправки должно происходить только после подтвержденного успешного результата.

## 7. Privacy and consent

Перед внедрением проверить:
- Какие данные собираются.
- Используются ли cookies или аналогичные технологии.
- Требуется ли согласие пользователя.
- Какие настройки приватности необходимы.
- Каковы сроки хранения данных.
- Какие сторонние платформы получают информацию.

Юридические требования и механизм согласия требуют подтверждения.

## 8. Validation

Перед релизом проверить:
- Корректность срабатывания событий.
- Отсутствие повторных событий без основания.
- Корректность параметров.
- Отсутствие персональных данных в payload.
- Корректность регистрации ошибок.
- Соответствие реализации утвержденной спецификации.
