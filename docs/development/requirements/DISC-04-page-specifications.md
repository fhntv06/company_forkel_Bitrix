# DISC-04 — Page Specifications

## 1. Purpose

Документ описывает требования к страницам Forkel на уровне, достаточном для создания прототипов и последующей реализации.

DISC-02 остается основным документом для общего списка страниц и пользовательских сценариев. DISC-04 раскрывает состав и поведение отдельных страниц.

## 2. Page specification template

Для каждой страницы фиксируются:

- Page ID.
- Название.
- URL pattern, если утвержден.
- Назначение.
- Пользовательская задача.
- Источники требований.
- Последовательность секций.
- Содержание каждой секции.
- Основные действия пользователя.
- Связанные страницы.
- Интерактивные элементы.
- Responsive behavior.
- Empty, loading, error и success states, если применимо.
- Acceptance criteria.
- Open questions.

## 3. Home page

Page ID: PAGE-HOME.

Назначение: представить компанию, ее предложение и ключевые направления, а также помочь пользователю перейти к целевому действию.

Структура секций определяется по утвержденному прототипу.

При спецификации проверить:
- Первый экран и основное сообщение.
- Основные CTA.
- Представление услуг или направлений деятельности, если применимо.
- Представление проектов, если предусмотрено.
- Дополнительные информационные секции.
- Нижнюю часть главной страницы.
- Переходы к контактам и проектам.
- Общий Footer.

Не придумывать окончательный состав секций, заголовки или бизнес-позиционирование.

## 4. Contacts page

Page ID: PAGE-CONTACTS.

Назначение: предоставить пользователю подтвержденную контактную информацию и способы связи с компанией.

Проверить наличие и требования к:
- Контактным данным.
- Формам или ссылкам связи, если предусмотрены.
- Карте и местоположению.
- Данным компании.
- Реквизитам.
- Нижним секциям страницы.
- Footer.

Контактные сведения и реквизиты должны поступать из подтвержденных источников.

## 5. Projects listing

Page ID: PAGE-PROJECTS.

Назначение: предоставить обзор проектов компании и возможность перейти к детальной информации.

Проверить:
- Состав карточки проекта.
- Изображение и текстовые данные.
- Название и дополнительные характеристики.
- Переход к детальной странице.
- Порядок отображения проектов.
- Пагинацию или загрузку дополнительных элементов, если необходимы.
- Empty state.
- Возможность фильтрации, если она предусмотрена.

Не добавлять фильтры или сортировку без подтверждения необходимости.

## 6. Project detail

Page ID: PAGE-PROJECT-DETAIL.

Назначение: представить информацию о конкретном проекте.

Определить:
- Правило формирования URL.
- Структуру данных проекта.
- Основной заголовок и описание.
- Галерею или медиаматериалы, если предусмотрены.
- Дополнительные характеристики.
- Связанные проекты или переходы, если предусмотрены.
- CTA и переходы к контактам.
- Поведение при неизвестном идентификаторе проекта.
- Поведение при отсутствии необязательных данных.

Структура должна поддерживать согласованный тип контента и не требовать отдельной уникальной реализации для каждого проекта без необходимости.

## 7. Search

Page ID: PAGE-SEARCH.

Статус отдельной страницы: определить по DISC-02.

Проверить:
- Где размещается поиск.
- Как пользователь вводит запрос.
- Как выполняется поиск.
- Какие страницы или сущности попадают в выдачу.
- Как отображается результат.
- Что происходит при пустом запросе.
- Что происходит при отсутствии результатов.
- Как обрабатываются ошибки.
- Как пользователь открывает результат.

Если поиск существует только как модальное окно, не создавать отдельную страницу без согласования.

## 8. Search modal

Component ID: MODAL-SEARCH.

Определить:
- Триггер открытия.
- Начальный фокус.
- Поле поиска.
- Действие запуска поиска.
- Представление результатов, если они выводятся внутри модального окна.
- Закрытие по кнопке и Escape.
- Поведение при клике вне окна.
- Управление фокусом.
- Мобильное представление.
- Связь с результатами поиска.

## 9. Feedback modal

Component ID: MODAL-FEEDBACK.

Определить:
- Триггер открытия.
- Состав полей.
- Required и optional поля.
- Валидацию.
- Отправку и блокировку повторного запроса.
- Loading state.
- Success state.
- Error state.
- Закрытие до и после отправки.
- Поведение при неудачной отправке.
- Требования к обработке персональных данных.

Поля, тексты согласия, получатель и механизм доставки сообщения должны быть утверждены до реализации.

## 10. Global layout

Для всех страниц проверить:
- Header.
- Global navigation.
- Основную область контента.
- Footer.
- Общие модальные окна.
- Общие CTA.
- Согласованность отступов и сетки с дизайн-системой.
- Мобильное поведение навигации.

Не дублировать полную спецификацию общего компонента на каждой странице. Использовать ссылку на DISC-05.

## 12. Acceptance criteria

Спецификация страницы готова к передаче, когда:
- Согласованы ее назначение и структура.
- Определены ключевые действия пользователя.
- Описаны существенные состояния и ошибки.
- Указаны источники данных.
- Определены связи с общими компонентами.
- Существенные открытые вопросы решены или явно вынесены на согласование.
