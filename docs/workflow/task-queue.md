# FORKEL — Task Queue

## 1. Назначение

Единый список задач проекта для всех ролей Claude. Используется для определения приоритетов, зависимостей и текущего статуса работы.

Подробные отчёты о выполнении хранятся в `work-log.md`, а актуальное состояние проекта — в `current-state.md`.

## 2. Статусы задач

- `BACKLOG` — задача ожидает выполнения.
- `READY` — задача подготовлена и может быть взята в работу.
- `IN_PROGRESS` — задача выполняется.
- `BLOCKED` — выполнение заблокировано.
- `REVIEW` — ожидает проверки.
- `DONE` — выполнена, критерии приёмки проверены.
- `CANCELLED` — отменена с зафиксированной причиной.

## 3. Приоритеты

- `P0` — критично для запуска или безопасности.
- `P1` — высокая важность для основных сценариев.
- `P2` — улучшение качества и полноты продукта.
- `P3` — необязательное улучшение.

Приоритет должен отражать ценность и риски, а не удобство выполнения.

## 4. Формат задачи

Каждая задача должна содержать:

- **ID:** уникальный идентификатор, например `DOC-001`.
- **Название:** короткое описание результата.
- **Роль:** Research / Implementation / QA / Documentation.
- **Приоритет:** P0–P3.
- **Статус:** один из статусов выше.
- **Зависимости:** ID задач, которые должны завершиться раньше.
- **Результат:** конкретный ожидаемый результат.
- **Критерии приёмки:** проверяемые условия завершения.
- **Документы:** необходимые материалы и исходники.

## 5. Очередь задач

### DOC-001 — Завершить базовую workflow-документацию

- **Роль:** Documentation
- **Приоритет:** P1
- **Статус:** IN_PROGRESS
- **Зависимости:** отсутствуют
- **Результат:** подготовлены документы `work-log.md`, `task-queue.md` и `handoff.md`.
- **Критерии приёмки:** документы созданы, ссылки между ними корректны, правила не противоречат `CLAUDE.md`.
- **Документы:** `CLAUDE.md`, `docs/workflow/*`.

### RES-001 — Изучить фактическое состояние frontend

- **Роль:** Research
- **Приоритет:** P1
- **Статус:** BACKLOG
- **Зависимости:** DOC-001
- **Результат:** описаны подтверждённые стек, маршруты, структура компонентов, стили и ограничения текущего frontend.
- **Критерии приёмки:** выводы подтверждены исходниками; неизвестные сведения явно отмечены.
- **Документы:** `current-state.md`, `docs/design/implementation-guide.md`.

### RES-002 — Проанализировать сайты-референсы

- **Роль:** Research
- **Приоритет:** P1
- **Статус:** BACKLOG
- **Зависимости:** RES-001
- **Результат:** подготовлены отдельный анализ референсов и их сравнение.
- **Критерии приёмки:** наблюдения отделены от предположений; определены применимые UX-паттерны и недостатки.
- **Документы:** `docs/design/reference-analysis.md`, `docs/design/comparison.md`.

### DES-001 — Подготовить дизайн-систему FORKEL

- **Роль:** Research
- **Приоритет:** P1
- **Статус:** BACKLOG
- **Зависимости:** RES-001, RES-002
- **Результат:** согласованный набор визуальных токенов, компонентов, состояний и адаптивных правил.
- **Критерии приёмки:** система учитывает требования и ограничения существующего frontend.
- **Документы:** `docs/design/design-system.md`, `docs/design/implementation-guide.md`.

### UI-001 — Реализовать первую согласованную страницу

- **Роль:** Implementation
- **Приоритет:** P1
- **Статус:** BACKLOG
- **Зависимости:** DES-001
- **Результат:** выбранная страница реализована в существующем frontend.
- **Критерии приёмки:** выполнены требования страницы, сохранена существующая функциональность, проверены адаптивность и доступные тесты.
- **Документы:** требования, дизайн-система и текущие исходники.

### QA-001 — Провести независимую проверку интерфейса

- **Роль:** QA
- **Приоритет:** P1
- **Статус:** BACKLOG
- **Зависимости:** UI-001
- **Результат:** отчёт о визуальных, адаптивных и функциональных дефектах.
- **Критерии приёмки:** замечания имеют приоритет, шаги воспроизведения и критерии исправления.
- **Документы:** `docs/qa/ui-review.md`, `docs/qa/acceptance-checklist.md`.

## 6. Правила управления очередью

- Не брать задачу в работу, если её зависимости не выполнены.
- Перед началом проверить, не выполняет ли её другая сессия.
- Не назначать `DONE` без проверки критериев приёмки.
- При блокировке указать причину и требуемое действие.
- При изменении объёма разделять задачу на самостоятельные части.
- Не добавлять задачи только ради заполнения очереди.
- После завершения обновить статус, `current-state.md` и `work-log.md`.

## 7. Текущая точка продолжения

Сначала завершить DOC-001. После этого проверить документацию и перейти к исследованию frontend и референсов.
