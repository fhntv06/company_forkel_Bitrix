# FORKEL — Task Queue

## 1. Назначение

Единый список задач проекта для всех ролей Claude. Используется для определения приоритетов, зависимостей и текущего статуса работы.

Подробные отчёты о выполнении хранятся в `work-log.md`, а актуальное состояние проекта — в `current-state.md`.

## 2. Статусы задач

- `BACKLOG` — задача ожидает выполнения.
- `READY` — задача подготовлена и может быть взята в работу.
- `IN_PROGRESS` — задача выполняется.
- `BLOCKED` — выполнение заблокировано.
- `REVIEW` — ожидает проверки.
- `DONE` — выполнена, критерии приёмки проверены.
- `CANCELLED` — отменена с зафиксированной причиной.

## 3. Приоритеты

- `P0` — критично для запуска или безопасности.
- `P1` — высокая важность для основных сценариев.
- `P2` — улучшение качества и полноты продукта.
- `P3` — необязательное улучшение.

Приоритет должен отражать ценность и риски, а не удобство выполнения.

## 4. Формат задачи

Каждая задача должна содержать:

- **ID:** уникальный идентификатор, например `DOC-001`.
- **Название:** короткое описание результата.
- **Роль:** Research / Implementation / QA / Documentation.
- **Приоритет:** P0–P3.
- **Статус:** один из статусов выше.
- **Зависимости:** ID задач, которые должны завершиться раньше.
- **Результат:** конкретный ожидаемый результат.
- **Критерии приёмки:** проверяемые условия завершения.
- **Документы:** необходимые материалы и исходники.

## 6. Правила управления очередью

- Не брать задачу в работу, если её зависимости не выполнены.
- Перед началом проверить, не выполняет ли её другая сессия.
- Не назначать `DONE` без проверки критериев приёмки.
- При блокировке указать причину и требуемое действие.
- При изменении объёма разделять задачу на самостоятельные части.
- Не добавлять задачи только ради заполнения очереди.
- После завершения обновить статус, `current-state.md` и `work-log.md`.
