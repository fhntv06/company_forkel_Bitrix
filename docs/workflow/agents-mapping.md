# Соответствие агентов Claude и ролей проекта

Агенты лежат в `.claude/agents/`. Этот документ связывает их с ролями из `roles.md` и `role-permissions.md`, не заменяя их. При конфликте действуют `role-permissions.md` и `github-workflow.md`.

| Агент | Роль в проекте | Зона изменений |
|---|---|---|
| `research-design` | Role A — Research & Design System | `docs/design/**` |
| `ui-implementation` | Role B — UI Implementation | файлы frontend/прототипа, названные в задаче |
| `qa-tester` | Role C — UI Review & QA | `docs/qa/**`; код не меняет |
| `bitrix-developer` | дополнительная роль: backend/Bitrix | PHP, компоненты, шаблоны Bitrix, API, интеграции из задачи |
| `content-manager` | дополнительная роль: CMS-контент | только через админку Bitrix; репозиторий не меняет |
| `orchestrator` | дополнительная роль: координация | не реализует; маршрутизирует, ведёт передачи и статус |

## Поток работы

1. Пользователь ставит задачу Orchestrator (`claude --agent orchestrator`).
2. Orchestrator определяет тип задачи и назначает исполнителя с ID задачи, разрешёнными файлами, критериями приёмки и веткой.
3. После реализации задачу проверяет `qa-tester` (независимо от исполнителя).
4. Статусы QA: `PASS` / `FAIL` / `BLOCKED` / `PARTIAL`.
5. `FAIL`: исполнитель исправляет подтверждённые дефекты (по ID), QA перепроверяет эти дефекты и делает короткую регрессию. Не более 3 кругов, затем эскалация пользователю.
6. `BLOCKED` и `PARTIAL` не считаются завершением.

## Правила

- Ветки: `role/<role>/<task-id>-<short-name>`; прямые изменения `main` запрещены, слияние только уполномоченным участником.
- `content-manager` не утверждает, что изменил контент в админке, без реального доступа к ней; иначе выдаёт процедуру со статусом NOT EXECUTED.
- Права агентов в `tools` — это ограничение инструментов, а не техническая изоляция; реальные ограничения задаются правами GitHub и защитой ветки `main` (см. `github-workflow.md`, раздел 9).
