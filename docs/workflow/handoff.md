# FORKEL — Session Handoff

## 1. Назначение

Передача задачи между сессиями и ролями Claude без повторного изучения всей истории чата.

Передача должна содержать проверенное состояние, необходимые файлы и конкретный следующий шаг.

## 2. Правила

- Передавать только информацию, необходимую следующему исполнителю.
- Не копировать полную историю переписки.
- Разделять выполненное, проверенное, незавершённое и предполагаемое.
- Перечислять реальные изменения в Git и файлах.
- Не заявлять о выполнении проверок, которые не запускались.
- Не перезаписывать изменения предыдущей сессии.
- Если задача завершена, явно указать, требуется ли следующая роль.

## 3. Шаблон передачи

### Handoff — YYYY-MM-DD

**Проект:** FORKEL

**Передающая роль:** Research / Implementation / QA / Documentation

**Следующая роль:** Research / Implementation / QA / Documentation

**Задача:** ID и краткое название из `task-queue.md`.

### Цель
Какой результат требуется получить.

### Выполнено
- Фактически завершённые действия.
- Созданные документы или реализованные функции.

### Изменённые файлы
- Путь к файлу — краткое описание изменения.

### Проверки
- Команды, тесты, скриншоты или сценарии, которые действительно проверены.
- Результат каждой проверки.
- Непроверенные области.

### Текущее состояние
Что уже работает, что находится в процессе и что требует исправления.

### Открытые вопросы и блокеры
- Неизвестные требования.
- Технические ограничения.
- Решения, требующие согласования.

### Следующие действия
1. Конкретный следующий шаг.
2. Следующий шаг после него, если необходим.

### Контекст для продолжения
Перечень документов и исходников, которые следующая сессия должна прочитать.

### Git
- Текущая ветка.
- Состояние рабочей директории.
- Commit, если создан.
- Незакоммиченные изменения, если есть.

## 4. Перед началом новой сессии

1. Прочитать `CLAUDE.md`.
2. Прочитать `docs/workflow/current-state.md`.
3. Прочитать актуальную задачу в `docs/workflow/task-queue.md`.
4. Прочитать этот handoff и документы, на которые он ссылается.
5. Проверить Git и фактическое состояние затрагиваемых файлов.
6. Продолжать работу с последнего подтверждённого шага.

Если handoff расходится с исходниками или Git, сначала установить фактическое состояние и исправить документацию.

## 5. Перед завершением сессии

1. Зафиксировать результаты работы.
2. Обновить статус задачи в `task-queue.md`.
3. Обновить `current-state.md`, если состояние проекта изменилось.
4. Добавить запись в `work-log.md`.
5. Обновить этот handoff для следующей роли.
6. Указать незавершённые действия и фактические результаты проверок.

Не дублировать подробности реализации, уже описанные в профильной документации.
