# FORKEL — Work Log

## Назначение

Краткая хронология существенных изменений проекта: документации, кода, дизайна, тестов и архитектуры.

Журнал помогает передавать работу между сессиями, не перечитывая историю переписки.

## Правила ведения

- Добавлять новую запись после завершения существенной задачи.
- Не переписывать старые записи; исправления оформлять отдельной записью.
- Указывать фактически изменённые файлы.
- Отделять выполненные действия от планов.
- Записывать результаты проверок и ошибки.
- Не дублировать полное содержание документов и технические логи.
- Для изменений кода указывать Git commit, если он создан.
- Не утверждать, что задача завершена, если критерии приёмки не выполнены.

## Формат записи

### YYYY-MM-DD — Название задачи

- **Роль:** Research / Implementation / QA / Documentation
- **Цель:** что требовалось сделать.
- **Результат:** что фактически сделано.
- **Изменённые файлы:** список основных файлов.
- **Проверки:** что запускалось или проверялось и каков результат.
- **Осталось:** незавершённые вопросы и дефекты.
- **Связанные задачи:** ID из `task-queue.md`, если назначен.
- **Git commit:** хеш или `не создан`.
