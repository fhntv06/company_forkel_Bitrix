1. Истёк срок пробной версии 1С-Битрикс (предупреждение выводится наверху каждой страницы, через 2 недели сайт заблокируется).

4. Корзина, оформление заказа и личный кабинет в `main` всё ещё работают на штатном `bootstrap_v4` с демо-свойствами одежды (`SIZES_SHOES`, `SIZES_CLOTHES`, `COLOR_REF`); доработка `TASK-009` не влита в `main`.
5. Ключевые e-commerce интеграции MVP — **платёжный шлюз (карты + СБП), доставка СДЭК, обмен с 1С, уведомления в MAX/Email (SMTP)** — не реализованы (в БД стоят демо-заглушки Битрикса).

## 3. Проверка БД 1С-Битрикс (факты)

1. **Настройки сайта (`b_lang`):**
   - `LID=s1`, `NAME="Интернет-магазин (Сайт по умолчанию)"`, `SERVER_NAME="localhost"`, `EMAIL="sale@localhost"`.
   - Последствие: `local/ajax/feedback.php` передаёт `EMAIL_TO => ''` (почта по умолчанию сайта), поэтому все заявки (обратная связь, звонок, покупка в 1 клик, анкета партнёра) адресуются на `sale@localhost`. В `b_event` сейчас `0` записей — реальная отправка почты не тестировалась и SMTP не настроен.
2. **Права на инфоблоки (`b_iblock_group`):**
   - Для всех 8 инфоблоков (`2: catalog`, `3: collections`, `4: catalog_offers`, `5: features`, `6: projects`, `7: solutions`, `8: interiors`, `9: pro`) задана **только одна строка**: `GROUP_ID=1, PERMISSION=X`.
   - `GROUP_ID=2` («Все пользователи») отсутствует полностью → все инфоблоки закрыты для гостей.
3. **Инфоблоки и наполнение (`b_iblock`, `b_iblock_section`, `b_iblock_element`, `b_iblock_property`):**
   - `catalog` (ID 2): `SECTION_PAGE_URL` = `/catalog/#SECTION_CODE_PATH#` (без завершающего `/`, хотя в `catalog/index.php` и Nginx ожидается со слэшем).
   - Разделы каталога: всего **3** (`rozetki`, `vyklyuchateli`, `termoregulyatory`). Нет разделов: **Рамки**, **Управление жалюзи**, **Диммеры**.
   - Товары: всего **3 тестовых товара** (`test-1-rozetka`, `test-2-rozetka`, `test-3-rozetka`) и **2 тестовых ТП** (`tp-test-1-rozetka`, `tp-test-1-rozetka-zolotoy`). У **всех 5 позиций** `QUANTITY=0` и `AVAILABLE=N` (купить невозможно).
   - Умный фильтр (`b_iblock_section_property.SMART_FILTER`): у всех свойств (`COLLECTION`, `MATERIAL`, `NEW`, `COLOR`) значение `NULL` — фильтр не включён.
   - Свойства: `ARTICLE` названо с опечаткой `"Артикуль"`; `MANUAL` имеет тип `S` (строка) вместо `F` (файл); отсутствует свойство `MECHANISM_TYPE` (для группировки характеристик по ТЗ §2.2).
   - `projects` (ID 6): `DETAIL_PAGE_URL` = `#SITE_DIR#/main_page/detail.php?ID=#ELEMENT_ID#` вместо `/projects/#ELEMENT_CODE#/`.
4. **Склады (`b_catalog_store`):**
   - 1 демо-запись: `ID=1`, `TITLE="Склад"`, `ADDRESS="пр. Московский д. 51"`. Реальные 3 магазина и склад (из `TASK-007`) в модуль `catalog` не заведены.
5. **Платёжные системы (`b_sale_pay_system_action`, `b_sale_bizval`):**
   - Установлены только демо-системы Битрикс: `Наличные курьеру (cash)`, `Наложенный платеж (cashondeliverycalc)`, устаревшие `ЮMoney / Банковские карты / Терминалы (yandex)`, `Сбербанк-квитанция (sberbank)`, `Банковский перевод (bill)`, неактивный `WebMoney`.
   - В `b_sale_bizval`: `PS_IS_TEST = Y`, `SELLER_COMPANY_BANK_ACCOUNT = 0000 0000 0000 0000 0000`, `SELLER_COMPANY_BANK_BIC = БИК 044525225`.
   - **Отсутствует:** реальный эквайринг (Альфа-Банк / ЮKassa / CloudPayments), приём карт + **СБП**, обработка webhook/callback, подтверждение оплаты и возвраты.
6. **Службы доставки (`b_sale_delivery_srv`):**
   - `Доставка курьером` (Configurable), `Самовывоз` (Configurable), неактивный `СПСР-Экспресс` (устаревший), `Без доставки`.
   - **Отсутствует:** **СДЭК** (обязателен в MVP по ТЗ §2.3; API-расчёт — Этап 2).
7. **Статусы заказов (`b_sale_status_lang`) и заказы (`b_sale_order`):**
   - Статусы заказа (`TYPE=O`): `N` («Принят, ожидается оплата»), `P` («Оплачен, формируется к отправке»), `F` («Выполнен»). Статусы отгрузки (`TYPE=D`): `DN..DF`. Соответствие статусам из ТЗ §2.4 («Новый», «В обработке», «Отправлен», «Отменён») не зафиксировано. Заказов в БД: `0`.
8. **Обмен с 1С (`b_option`):**
   - Настройки выгрузки каталога из 1С (`1C_*` модуля `catalog`) отсутствуют; у модуля `sale` только дефолтные параметры. Тестовый обмен не проводился.

## 5. Что не проверялось (ограничения локального аудита)

- Реальная отправка почты и доставка в MAX (нет SMTP/API-ключей).
- Реальная оплата и webhooks эквайринга (нет тестового/боевого шлюза).
- Реальная выгрузка из 1С (нет доступа к базе 1С заказчика).
- Замеры Lighthouse/PageSpeed на мобильной сети и реальных устройствах (локальный Docker на Windows не отражает production TTFB).
- Кросс-браузерная проверка в Firefox, Safari, Opera, Edge (проверено в Chromium/Playwright).
