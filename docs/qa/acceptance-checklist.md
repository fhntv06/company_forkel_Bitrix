# FORKEL — Критерии приёмки

> Проверяет роль QA (`docs/qa/**`). Отмечать только фактически выполненные проверки: `PASS`, `FAIL` (с дефектом в `ui-review.md`), `NOT CHECKED` (с причиной). Подтверждённое отделять от предположений.

## V3 — `prototype/homepage-v3/` (задача UI-011, приёмка QA-002)

Источник требований: `task-queue.md` (UI-011), `decisions.md` DEC-004…DEC-008, `homepage-requirements-map.md` 9.6.

### 1. Запуск и независимость

- [ ] Открывается как `http://localhost:8080/homepage-v3/index.html` при `python3 -m http.server 8080 --directory prototype`; ни одна страница не ссылается на файлы `prototype/homepage-v2/`.
- [ ] Файлы `prototype/homepage/` и `prototype/homepage-v2/` не изменены (`git diff` относительно коммита до V3).
- [ ] Нет Bitrix, backend, сборки и сторонних библиотек.

### 2. Страницы и переходы

Каждая страница открывается прямой ссылкой и из навигации; шапка и подвал одинаковы по составу и поведению.

- [ ] Главная: все блоки H-01…H-10, включая нижнюю часть; статичный Hero без слайдера; кнопки «Смотреть коллекции» и «Собрать в подборе».
- [ ] Каталог и страницы коллекций (фильтры, поиск по каталогу, сортировка, состояние в адресе сохраняется при возврате).
- [ ] Детальная страница товара (фото, название, артикул, цена, наличие, цвета, количество, «В корзину», характеристики из трёх групп, связанные товары).
- [ ] Конфигуратор (раздел 5).
- [ ] Корзина (раздел 5).
- [ ] Контакты: способы связи, карта (или аккуратная заглушка без выдуманного адреса и ключа), данные компании и реквизиты — заглушки.
- [ ] Проекты: список; карточки ведут на детальные страницы.
- [ ] Страница проекта: обложка, описание, галерея; ссылки на коллекции и товары только при обоснованной связи.
- [ ] Страница результатов поиска.
- [ ] Страницы и сценарии V2 не пропали (каталог, товар, корзина, подбор).
- [ ] Нет битых внутренних ссылок и якорей; нет ссылок `href="#"` без объяснённого поведения.

### 3. Поиск и модальные окна

- [ ] Поиск открывается из шапки на всех основных страницах.
- [ ] Результаты по демонстрационным товарам и проектам; каждый результат ведёт на свою страницу.
- [ ] Пустой запрос и «ничего не найдено» обработаны отдельными состояниями.
- [ ] Закрытие по Escape, по крестику и по клику вне окна; фокус уходит в окно и возвращается на кнопку, вызвавшую его; Tab не выходит за окно; фон не прокручивается.
- [ ] Форма обратной связи: имя, телефон или email, сообщение, согласие; ошибки показаны у поля и доступны скринридеру; без согласия отправка невозможна; подтверждение явно демонстрационное, реальная отправка не имитируется (DEC-007).

### 4. Подбор и корзина

- [ ] Последовательность: коллекция → тип изделия → цвет рамки → цвет механизма; тип отделён от цвета механизма; «Цвета фона» нет.
- [ ] Шесть цветов в каждом наборе: белый глянцевый, белый матовый, золотой, кашемир матовый, серый, чёрный матовый; активный выбор, название и образец видны.
- [ ] Превью меняется при выборе цвета рамки и цвета механизма (слои из `prototype/assets/images/`).
- [ ] Комплект добавляется одной позицией «Комплект» с составом и демо-ценой; повторное добавление увеличивает количество.
- [ ] Счётчик корзины согласован с позициями; количество 1–99; удаление; пустое состояние со ссылкой в каталог; данные сохраняются после перезагрузки.
- [ ] Демо-цена и артикул комплекта помечены; формула не выдана за утверждённую.

### 5. Изображения и данные

- [ ] Все изображения загружаются (нет 404 и пустых блоков), хранятся локально, кадрирование корректно (нет искажения пропорций и обрезки изделия).
- [ ] SVG-заглушки не остались там, где заявлены фотографии; заменённые места перечислены в отчёте.
- [ ] Стоковые фото не названы продукцией FORKEL; материалы Kollinger не выданы за товары FORKEL; лицензия и источник каждого файла указаны в README V3.
- [ ] Неподтверждённые цены, артикулы, остатки, характеристики, контакты и реквизиты помечены («демо», «заглушка», «Уточняется владельцем»); одинаковые значения не размножены по товарам, где это нелогично.
- [ ] Нет сравнения и избранного, нет неподтверждённых функций.

### 6. Сетка и адаптивность

Ширины: 360, 390, 768, 1024, 1280, 1440, 1920 px.

- [ ] Нет горизонтальной прокрутки ни на одной странице и ширине.
- [ ] Товарные сетки (ориентиры владельца): от 1440 px — 4–6 карточек; 1024–1439 — 3–4; 768–1023 — 2–3; мобильные — 1–2. Число колонок зависит от доступной ширины.
- [ ] Контент не растянут на 1920 px; карточки и шрифты не чрезмерно крупные.
- [ ] Цели нажатия ≥ 44 px; текст ≥ 14 px; контраст текста не ниже 4,5:1 (проверено, а не предположено).
- [ ] Первый экран на 360×640 содержит `h1` и основное действие.

### 7. Доступность и устойчивость

- [ ] Обход с клавиатуры: порядок логичен, фокус виден на всех интерактивных элементах, нет ловушек вне модальных окон.
- [ ] У кнопок и ссылок есть доступные названия; один `h1` на странице; осмысленные `alt` у содержательных изображений.
- [ ] `prefers-reduced-motion` учтён.
- [ ] Ошибок и предупреждений в консоли нет; нет неудачных запросов.
- [ ] Повреждённое или недоступное `localStorage` не ломает страницы.

### 8. Что остаётся вне проверки (указать в отчёте)

Реальные устройства, Safari и Firefox, скринридеры, автоматический аудит доступности, скорость загрузки — отмечать `NOT CHECKED`, если не проверялись.

### 9. Отчёт

Путь к V3 и запуск; реализованные страницы и сценарии; выполненные проверки (с фактическим результатом); отсутствующие данные и материалы; оставшиеся ограничения; дефекты с приоритетом P0–P3, шагами воспроизведения и критерием исправления (`roles.md`).
