# FORKEL — переход с V3 на V4

> **Статус:** ПЛАН, составлен 2026-11-03 (UI Implementation) по запросу владельца; решения владельца — раздел 9.1. Выполнено: подключён шрифт Montserrat (раздел 2.1). Остальные этапы не начаты.
> **Источники:** `prototype/homepage-v3/` (структура, функции, данные), `prototype/homepage-v4/` (дизайн, главная), `docs/design/parts_design_for_pages.md`, `docs/workflow/current-state.md` (4.4, 4.5).
> Документ нужен, чтобы при переносе ничего не потерять. Этапы небольшие: один этап — одна страница, секция, функция или общий компонент.

## 1. Цель и принцип

**Цель:** `prototype/homepage-v4/` совпадает с V3 по **структуре** — страницам, разделам, секциям и функциям, а выглядит по **дизайну V4**.

**Принцип:**

| Что | Откуда берём | Примечание |
|---|---|---|
| Состав страниц, секций, порядок, ссылки между страницами | **V3** | Все 16 страниц V3 должны быть в V4. |
| Функции (корзина, избранное, поиск, подбор, окна, кабинет, копирование, слайдер и т.д.) | **V3** | Поведение, ключи хранения, данные — как в V3. |
| Данные, картинки, цвета товаров и подбора | **V3** | `data.js`, `assets/images/**`, палитры F70 / F55. |
| Внешний вид: палитра, шрифт, радиусы, кнопки, карточки, шапка, подвал, сетка | **V4** | Токены и компоненты из `homepage-v4/styles.css`. |
| Главная страница | **V4 как есть** | Заказчику нравится, **не переделываем**; дополняем только секциями, которых в V4 нет (раздел 5, этап I2). |
| Подбор (configurator) | **Компонент и вид из V4**; **логика, шаги, цвета и фото из V3** | Решение владельца: дублирование убираем, берём V4. |

**Если вид V4 и структура V3 противоречат** — структура V3 остаётся, вид подгоняется под V4 (не наоборот). Спорные случаи — в раздел 9 (вопросы), без самостоятельных решений.

## 4. Архитектурные решения для перехода

**Решение A (рекомендация): V4 сохраняет собственный `styles.css` для главной; страницы V3 подключают его токены.**

- Токены V3 (`--fk-*`) связываются с токенами V4 одним файлом `css/v4-skin.css`: `--fk-ink → --ink`, `--fk-surface → --surface`, радиусы, шрифт, акцент `--fk-bright → --yellow` и т.д. Это «слой оформления».
- Разметка и скрипты V3 сохраняют классы `fk-*` и атрибуты `data-*`, чтобы **не переписывать логику**. Компоненты, которых нет на главной V4 (фильтры каталога, корзина, форма заказа и др.), оформляются в стиле V4 по правилам раздела 2.
- Компоненты, которые есть и в V4 (шапка, подвал, карточка товара, кнопки, подбор), собираются **один раз** в стиле V4 и подключаются на все страницы, включая главную V4. Главная V4 при этом визуально не меняется.

**Решение B (альтернатива):** переписать все классы V3 на классы V4 (`.btn`, `.card` и др.). Плюс — единая система имён; минус — переписывание всей логики карточек, фильтров, корзины и риск потери функций. **Не рекомендуется.**

Решение владельца: «стили как в V4» (раздел 9.1) — реализуем по варианту A.

**Прочее:**
- Папка V4 остаётся статичной (HTML/CSS/JS, без сборки и зависимостей), как V3.
- V1–V3 не изменяются; V3 после начала перехода замораживается (правки — только в V4), кроме исправлений дефектов по решению владельца.
- Ключи хранения (`fk-demo-cart-v1`, `fk-demo-fav-v1`, `fk-demo-auth-v1`) сохраняются.
- Палитра: **палитра V4** (решение владельца 2026-11-03). Цвета заказчика из V3 в V4 не применяются.

## 6. Проверки паритета (ничего не забыть)

Для каждого этапа и в конце (F1). Скрипты проверок лежат вне репозитория (сессия исполнителя); при необходимости их можно добавить в репозиторий отдельным решением.

1. **Страницы:** каждая из 16 страниц V3 есть в V4 по тому же имени файла и открывается без ошибок консоли и HTTP.
2. **Секции главной:** все секции из 3.2 присутствуют; секции V4 на месте; порядок — по решению владельца.
3. **Функции (сценарии):** добавить в корзину → счётчик → страница корзины → оформление; избранное: добавить, убрать, очистить; поиск: окно → результаты; подбор: шаги → комплект в корзине; кабинет: вход, выход; окна: обратная связь, звонок; каталог: фильтры, сортировка, сохранение; товар: цвета, копирование, скачивание, окно видео; «Готовые решения»: слайдер, точки, блок товаров; соцсети: виджет и подвал.
4. **Ключи хранения:** `fk-demo-cart-v1`, `fk-demo-fav-v1`, `fk-demo-auth-v1` совпадают с V3.
5. **Данные:** количество товаров, категорий, коллекций, цветов в V4 равно V3; цены и артикулы не придуманы заново.
6. **Дизайн:** главная V4 совпадает с эталоном M0; токены V4 не изменены; на страницах V3 нет цветов и радиусов, не взятых из токенов V4.
7. **Адаптивность и доступность:** раздел 5, правило (3).
